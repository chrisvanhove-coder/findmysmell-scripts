# Что дальше

Состояние на 2026-09-11. Ветка `claude/web-flow-site-assessment-lctz2k`.
Файл написан так, чтобы можно было продолжить с нуля, не поднимая переписку.

## Где мы сейчас

Прод не тронут и работает как работал. Вся новая работа в `web/`, старые
скрипты в корне по-прежнему отдаются на живой сайт через jsDelivr — про это
отдельно в `LEGACY.md`, их нельзя переименовывать и перемещать.

Сделано:

- **Бэкап Webflow** — `webflow/`. CSS страницы результата, движок подсчёта
  архетипа с таблицей весов, site-level код. До этого существовало в одном
  экземпляре внутри Webflow.
- **Данные** — `web/src/data/`. Контент архетипов (EN + FR), каталог из
  113 позиций CMS, таблица весов на 164 ответа, тексты квиза.
- **Подсчёт архетипа** — `web/src/lib/scoring.ts`. Сверен с продом:
  0 расхождений на 200 000 прогонов (`tools/parity-check.mjs`).
- **Подбор по осям** — `web/src/lib/matching.ts`. Сверен: 0 расхождений на
  448 комбинациях (`tools/matching-parity.mjs`). Ничьи (40% случаев)
  разрешаются приоритетом по эмоции, выведенным из данных.
- **Квиз** — `web/src/app/[locale]/quiz/[question]/`. 24 вопроса на одном
  маршруте, переходы без перезагрузки (проверено: 1 загрузка документа на
  весь проход вместо ~19), ветвление по эмоциям, поиск по странам,
  согласие на исследование.
- **База** — схема Drizzle, миграция и идемпотентный сид, проверены на
  настоящем Postgres через PGlite.

## Осталось сделать, по порядку

### 1. Привязать страницу результата к ответам пользователя

Сейчас `/[locale]/result/[archetype]` берёт оси из параметров адреса
(`?s=&r=&p=`) — это было нужно для предпросмотра при работе над дизайном.
Надо: после квиза читать реальные ответы из хранилища, считать архетип
через `resolve()`, оси через `preferencesFrom()`, эмоцию через
`emotionBiasFrom()` и показывать результат по ним.

Развилка, которую надо решить: адрес с архетипом (`/result/ceo`) удобен для
шеринга и OG-картинок, но сам результат зависит от ответов. Разумно
оставить `/result/[archetype]` как канонический серверный адрес для шеринга,
а персонализацию (какой именно флакон) доводить на клиенте поверх него.
Тогда вернётся и предгенерация страниц, которую сейчас сломали параметры.

Не забыть: старый код при отсутствии `quiz_result` затирал
`document.body.innerHTML` заглушкой «PLEASE COMPLETE THE QUIZ FIRST».
Нужно нормальное пустое состояние.

### 2. Писать прохождения в Postgres вместо Google Sheets

Сейчас прод шлёт результат в Google Apps Script
(endpoint зашит в `webflow/page-result-footer.html`).
Таблицы уже есть: `submissions` (ответы, баллы, победитель, согласие)
и `subscribers` (почта, отдельно — это персональные данные).

Надо: route handler в Next, запись один раз за прохождение,
уважать `consent_aggregate` — при отказе не писать ответы в исследование.
Плюс перенести форму подписки на письмо со страницы результата.

### 3. Французские и русские тексты квиза

Сейчас все три локали показывают английский: `quiz.en.json`,
`question-titles.ts` и `content.ts` для `ru` отдают EN.

Надо выгрузить из Webflow тексты вопросов и ответов для `/fr/` и `/ru/`
(страницы перечислены в `webflow/README.md`, забираются через
`data_element_tool` → `query_elements` по атрибуту `data-answer-key`
и по типу `Heading`). Осторожно с лимитом Webflow — на 24-м запросе подряд
прилетел 429, лучше батчами по 6-8.

Русского контента результатов не существует вовсе — только вопросы.
Это отдельный разговор с заказчиком.

## Открытые вопросы к заказчику

- **SEXY.** Приоритет по эмоции у него почти нулевой
  (−0.04 / +0.06 / +0.11), потому что веса ответа размазаны между четырьмя
  архетипами. Ничьи он формально разрешает, но выбор там опирается на
  крошечные различия. Если для SEXY важно конкретное направление —
  нужно решение.
- **Шрифт HIGHCRUISER.** Файла нет, стоит Fraunces. Если файл найдётся,
  менять только `--fms-display` в `web/src/styles/global.css`.
- **24 позиции каталога без осей S/R/P.** В подборе не участвуют
  (движок берёт только те, у кого заполнены все три). Либо проставить оси,
  либо убрать из коллекции.
- **Расхождение share-карточек.** У HUG, OUTOFTIME и SUMMER карточка
  показывает не тот парфюм, что на странице: данные карточек зашиты в
  `result-shared15.js`, а главный парфюм в CMS с тех пор поменяли.
  В новой версии карточка будет читать тот же каталог.
