## Поведение для пользователя

- Back остаётся доступным. Ответ на первый вопрос при возвращении назад больше не начинает другое прохождение.
- Нажатие BEGIN / Start the quiz начинает чистое прохождение: сбрасываются ответы, все Other, финальный текст, решение об исследовании и состояние отправки. Идентификатор браузера и общий счётчик — отдельный механизм, в этих исправлениях он сохраняется.
- Изменение Q_EMO удаляет ответы и Other неактуальных эмоциональных веток. Общие ответы остаются. Возврат по истории на неактуальную ветку направляет на выбранную.
- Каждое изменение сохраняется локально в браузере. Итоговый архетип рассчитывается при завершении Q_OPEN. Если обязательный вопрос пропущен, пользователь возвращается к нему. Семантический анализ свободного текста не добавлялся: формула архетипа остаётся прежней.
- Изменение после результата при повторном завершении обновляет ту же запись. Счётчик прохождений не увеличивается. Номер версии защищает свежие ответы от запоздавшего запроса со старым состоянием.
- Ответы и Other обновляются одной транзакцией. Удалённые Other не остаются в базе.
- Отправка считается успешной только после подтверждения сервера. При ошибке видна кнопка повтора; есть две автоматические повторные попытки и повтор после восстановления сети. Обновление страницы также повторяет неподтверждённую отправку.
- Финальный текст ограничен 2000 символами, как и серверное поле.

## Сохранение и согласия

По уточнению заказчицы ответы и архетип сохраняются и при отказе от исследования; значение отказа остаётся `false`. Фильтрация существующей выборки по первым прохождениям не изменялась. Согласие на email независимо.

Сервер принимает корректные неполные наборы для последующего разбора, но отклоняет выдуманные вопросы, несоответствующие им варианты, неактуальные ветки и Other без выбранного варианта Other. В админке видна неполнота, в CSV добавлены `answers_complete` и `missing_questions`. Это полнота обязательных вопросов выбора, а не юридическое согласие или обязательность финального свободного текста.

Автоматическая отправка каждого незавершённого шага в базу не добавлялась. Неполные записи маркируются, если поступили на API; обычный интерфейс отправляет завершённое прохождение.

## Письмо

Ранее API искал полученный `perfumeId` только среди четырёх запасных вариантов архетипа. Теперь он находит точный флакон во всём активном каталоге соответствующего архетипа. Неизвестный или чужой ID вызывает ошибку, а не подмену. Если ID не передан, письмо содержит только архетип, без придуманного флакона. Неизвестный набор альтернатив не восстанавливается по умолчанию.

## Импорт

В подписчики переносятся только адреса с явным `consent_email=true` (также исходные 1/yes/да). False и отсутствие значения не считаются согласием. Прохождения этих людей сохраняются независимо от email.

Импорт не отправляет письма и больше не придумывает дату прошлой доставки. `sent_at=null` означает отсутствие подтверждения доставки. При повторном импорте существующие подписки не переписываются: более новое согласие не затирается историческим.

**Ранее ошибочно импортированные рабочие записи не исправлены:** нет доступа к рабочей БД и исходной выгрузки для безопасного сопоставления. Повторный импорт сам по себе их не исправит; нужен отдельный разбор по исходным согласиям.

## Установка

Перед запуском новой версии применить миграции обычным процессом проекта:

```sh
cd web
npm ci
npm run db:migrate
npm run build
```

Новая миграция `0006_quiz_revision.sql` добавляет `submissions.revision` с начальным значением 0 для старых строк. Использовать правильный DATABASE_URL целевого окружения. Рабочая база и деплой в рамках этой задачи не менялись.
