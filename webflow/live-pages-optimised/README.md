# Готовые к заливке страницы: картинки через трансформации Cloudinary

Те же файлы, что в `../live-pages/`, но каждая ссылка на
`cdn.prod.website-files.com` заменена на Cloudinary с трансформацией.
Отличий, кроме ссылок, ноль — проверено построчным диффом с
замаскированными URL. JS каждой страницы разбирается (`new Function`).

## Зачем

Страницы вопросов подгружают **все** фотографии ответов сразу, в цикле
`Object.values(imageMap).forEach(url => { const img = new Image(); img.src = url; })`.
Ссылки идут без трансформаций, то есть отдаются оригиналы PNG.

## Пресеты

- фон на весь экран (`q-atmos`, `q-yourself`, `q-celebrate`,
  `q-calm-now`, `q-emo`) — `c_limit,w_1400/f_auto/q_auto`
- фон плитки ответа, оригиналы 1920×480 (семь страниц-веток эмоции)
  — `c_limit,w_1000/f_auto/q_auto`

`c_limit` выбран сознательно: он уменьшает, но никогда не увеличивает,
поэтому картинка меньше пресета останется как есть.

## Чего эти файлы не лечат

- `q-gender` и `q-skin-behavior` грузят видео (mp4 из Cloudinary), а не
  фото. Там нужен отдельный разговор про `q_auto` для видео и про постер.
- Сама стратегия «предзагрузить все ответы сразу» остаётся. Даже
  сжатые, девять фонов — это девять запросов в момент открытия. Правильно
  было бы грузить по наведению плюс маленькую превьюшку заранее, но это
  уже изменение поведения, а не ссылок.
- Оригиналы в Cloudinary остаются PNG на 357 МБ. Трансформации их не
  трогают, отдаётся производная. Перезаливать ничего не нужно.
